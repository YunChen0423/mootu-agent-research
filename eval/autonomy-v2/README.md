## 输入、输出和职责

仍输入带时间戳和已确认说话人的整场逐字稿。模型在每个检查点看到最近讨论、程序保留的意愿状态，以及所有尚未确认已审查的已完成发言（意愿提取不受最近 8 条截断影响）。`reviewed_source_ids` 必须覆盖工具给出的全部待审来源，否则程序拒绝本次评估并要求补齐；`preference_updates` 也不可省略，没有意愿时明确返回空数组。模型确认已审查仍不能证明其语义解释正确。模型通过 `preference_updates` 识别明确意愿；每项必须提供来源 ID 和逐字原话。

程序验证来源已经发生、说话人在名单内、引用确实存在，然后保存：

- `decline_invitation`：本人不愿被点名；直到本人明确 `resume_invitation` 才解除。普通发言不自动撤销。
- `quiet_period`：请求暂时停止全组提问；模型提取明确时长，程序从该发言结束计时，按 `[end, end + duration)` 生效。`end_quiet_period` 只能提前解除该说话人自己的请求，多人请求分别管理。

状态在每个已批准决策的 `autonomyState` 中；`preferenceAudit` 显示接受/拒绝的提取，`blockedCandidates` 显示被拦截候选及原因。模型后续不重复提及意愿，状态也不会消失。到期只解除限制，不强制机器人说话。拒绝个人点名不会禁止对全组的合适问题。

附带修复：单人会话不能据相对低参与点名；不合格的最高分候选不再挡住其他合格候选。未降低原效用差 8 或自报置信度 60 的门槛。

## 限制

这是“模型解释语义、程序管理已提取状态”，不是程序独立理解语言。逐字引用验证只能验证出处，不能证明模型解释正确；漏提取、反话、引用他人或时长解释错误仍需评测。没有明确时长或超过 30 分钟的思考请求暂不自动设定期限，模型应报告缺少证据；无期限暂停尚未实现。直接名称检测是保守字面检查，可能误拦同字词，也不能覆盖昵称或间接称呼。

当前网页麦克风输入没有可靠说话人身份和逐句结束时间，不能套用逐成员意愿保证；这次完整复测针对导入逐字稿路径。实时接口只有收到已确认来源和显式会话时钟时才能更新成员状态。未配置模型时仍是明确标注的规则回退，不宣称具备语义意愿识别。

采样仍为 Provider 默认，元数据明确记录，不宣称温度为零或完全确定。测试是作者合成开发集，未独立标注，约束通过不证明策略总是恰当或真人讨论获益。原有 12 用例全量重复、方案去重和长期方案记忆仍需后续实验。
