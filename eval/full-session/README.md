# 整场讨论输入示例

这是一份 15 分钟、4 位成员、60 条带时间戳发言的合成讨论。前 5 分钟探索想法，中间 5 分钟展开约束，后 5 分钟比较与取舍。它是完整输入链路示例，不是真人录音，也没有独立人工金标准。

把 input.json 上传到页面，或者作为 POST /api/analyze 的 body。系统默认每 30 秒做一次判断，输出从 0 到 900 秒共 31 条 events。

整场一次上传不代表模型在最早时刻就读完整场。模型每次只看最近 60 秒里最多 8 条已完成发言，以及过去已批准的决策记忆。因此后面的信息不会提前影响前面的决策。当前记忆不等于完整逐字稿历史的可靠长期摘要，跨很长时间的偏好和早期方案仍需单独测试。

输出结构是 mode、model、analysis、events、trace、execution。每条 event 含 time、stage、strategy、target、reason、evidence、metrics、candidates 和 followUp；可按时间轴逐条查看。

当前示例仅包含参与者讨论。宏观破冰、投票、结束等事件由 SessionHarness 单独处理；API 的讨论决策分析不等于一个已完整实现的自动会议生命周期执行器。较长会话会增加模型请求次数、等待时间与费用。

本例已提供 expected.json（31 条决策及时间戳的结构预期）和 rule-output.json（实际规则输出）。真实模型完整输出链接会保存在上一级 STABILITY.md。这些结构预期不能代替逐条主持质量评价。
