# 版本怎么分

只维护一个仓库，一条日常开发主线 `main`，再用固定标签保留重要节点。标签是对某次提交起的固定名字，不是又复制一份文件夹。

首次上传使用 GitHub 连接器，它支持创建分支，但没有创建标签的接口。因此 GitHub 上目前用 `snapshot/v0.1.0-demo` 和 `snapshot/v0.2.0-research-baseline` 两个分支保存对应版本；本地仍保留下表中的标签。快照分支不用于日常修改。后续配置好 Git 推送认证后，可以补齐远端标签；当前请用快照分支查看历史版本。

|名字|用途|以后怎么用|
|---|---|---|
|`main`|当前研究代码与评测|日常修改都从这里开始|
|`v0.1.0-demo`|保留原演示发布包的源代码快照|需要重现旧演示时按此标签检出|
|`v0.2.0-research-baseline`|移除演示编排、具备测试集与三轮模型结果的研究基线|后续优化以它作为对照，不改写旧结果|

`v0.1.0-demo` 只记录演示源代码；不包含密钥、依赖、生成产物和部署身份配置。它不是对线上服务、外部依赖或真实硬件状态的完整备份。

当前研究基线的结果：12 个决策用例各三轮，30/36 次符合预设标签，7/12 个用例三轮都符合；18 个标注检查点中 12 个三轮决策元组一致。另有 15 分钟整场输入链路验证。见 `eval/STABILITY.md`。这些是合成输入的初步结果，不是研究效果认证。

以后一次独立改动建一个短期分支，例如 `fix/invitation-policy`；测试和审查后合并回 main。形成新的可比较基线时，再新增 `v0.3.0-...` 标签，不移动或覆盖旧标签。暂时不需要维护长期 demo 分支；确实要修改演示版时再从 demo 标签建立分支。

新的一次模型实验保存在新的结果目录，记录模型、配置和数据版本；不要覆盖 `eval/results/stability/` 下的历史实验。API 密钥只放本地 `.env`，不要提交。
