## 保留的设计参数

60 秒测量窗、70 秒低参与阈值、35 秒全局冷却、70 秒邀请冷却、效用权重、0–100 分转换和 60/8 的模型置信度/效用门槛仍是可配置的工程假设，并非文献验证常数。必须在训练/开发会话上校准，然后冻结到独立测试集；不能根据测试结果反复调参。邀请目标的保护采用当前最少参与成员与份额阈值，不声称衡量个人意愿或公平性。

## 尚未实现或验证

- 真机、可靠说话人分离、姿态/生理推断均未实现；dispatch 仍为 simulated。浏览器现场模式没有可靠分人证据，因此阻止模型点名邀请。
- 规则基线只做浅层词汇和字串新颖度，不能可靠识别语义收敛；分数是启发式代理量。未发言时参与/发散分数仍有先验值，不能解释成已测心理状态。
- 可视化最多 6 个 Pod，评测 API 可处理更多参与者；多人重叠发言按每人时长统计，不等于会议墙钟时长。
- `session-router.mjs`、`workflows.mjs` 和 `skills.mjs` 保留架构接口；通用工作流执行器仍是原型。回放 harness 会校验候选/票据，但不等于已实现自动破冰和投票设备控制。
- 宏观阶段优先支持结构化事件；文本回放仅有限支持中文提示与明确选择。多轮投票/撤票/重新投票需要显式轮次协议，当前只支持一个冻结候选版本、首票有效、全员法定人数。
- 不把“投票结束”的口头宣告当逐人票据。缺少设备记录的历史演示逐字稿可能显示缺票，这是证据缺失。
- 离线完成发言才可见，带来最多一个发言周期的延迟。流式识别需逐片段时间戳，不能把完整后续句子提前暴露。
- 每窗顺序模型调用增加延迟/成本；真实模型已做一轮合成评测，逐窗设置了 180 秒中止期限；超时重试、精确成本、稳定性与长会话表现仍未验证。
- 研究副本不带部署凭据，没有发布。构建成功只证明可打包。

- 当前 trace 保存生命周期摘要和最终决策/dispatch，不包含完整 provider 请求与原始工具返回；真实模型研究还需补充脱敏后的原始记录与 usage。
